送信元サーバーで確認すること

送信元サーバー画面では、保存済みの DMARC 解析結果を送信元 IP ごとに集計します。レコードを 1 件ずつ追う前に、問題が多い送信元から確認できます。

列の意味

列意味
送信元 IPDMARC レポートに記録されたメール送信元 IP アドレスです。
メール数その IP から送信されたと報告されたメール件数です。
ドメイン数その IP から送られたメールの From ドメイン（組織ドメイン）の数です。詳細画面の「観測ドメイン」には、From ドメインが最大 4 件まで表示されます。
確認が必要な件数の列（「要確認」）なりすまし疑い・自社送信元の認証失敗・判定保留・読取エラーに分類されたメールの合計で、運用者が確認すべき件数です。転送経由の可能性は含まれません。
DMARC 成功率DMARC 評価が pass になった割合です。0.0% の場合は認証失敗が集中していないか確認してください。
推定サービス送信元のサービス名を表示する列です。現行版の取り込みでは値が設定されないため、「-」と表示されます。詳細画面の「推定信頼度」も同様です。
設定照合送信元 IP が、設定画面に登録した自社 IP・転送 IP と一致するかを示します（「自社IP登録あり」「転送IP登録あり」「登録なし」）。何も登録していないと、すべて「登録なし」と表示されます。一致していても DMARC が失敗している場合は SPF / DKIM / DMARC 設定を確認してください。

確認の順番

  1. まず、確認が必要な件数が多い行を確認します。
  2. 設定照合が「登録なし」の行は、正規の送信元かどうかを確認します。自社のサーバーなら設定画面に登録し、正当な転送サーバーなら「転送サーバーとして登録」（第 3 章）で登録します。
  3. 「自社IP登録あり」で DMARC 成功率が低い場合は、自社メールサーバーの SPF / DKIM / DMARC 設定を確認します。
  4. 行を選択し、詳細の関連レコードから個別レコードの結論と対応案を確認します。
  5. 必要に応じて CSV エクスポートし、チーム内で送信元 IP の確認を分担します。

CSV の列

CSV は UTF-8（BOM 付き）で出力され、Excel でそのまま開けます。列名は英語で固定です。

出力元列（左から順）
レコード一覧（20 列）record_hash, report_id, org_name, source_ip, count, header_from, spf_result, dkim_result, spf_aligned, dkim_aligned, dmarc_pass, classification, severity, internal_asset_match, known_forwarder_match, known_sender_service_match, provider_name, provider_confidence, date_range_begin, date_range_end
送信元サーバー一覧（22 列）source_ip, total_messages, record_count, domain_count, header_from_domains, success_messages, suspicious_messages, config_error_messages, forwarded_messages, needs_review_messages, parser_error_messages, dmarc_fail_messages, spf_fail_messages, dkim_fail_messages, dmarc_pass_rate, last_seen_unix, provider_name, provider_confidence, internal_asset_match, known_forwarder_match, known_sender_service_match, highest_severity

What to check on Sending Servers

The Sending Servers screen groups saved DMARC analysis results by source IP. It helps you start with the servers that have the most items needing attention.

Column meanings

ColumnMeaning
Source IPThe source IP reported in DMARC aggregate reports.
Mail countThe number of messages reported from that IP.
Domain countThe number of From domains (organizational domains) of the mail sent from that IP. The detail area's "Observed domains" shows up to 4 of the From domains.
Count of items to check ("Needs review" column)The total number of emails classed as Spoofing suspected, Authentication failures from your own senders, Pending review, or read errors — the items an operator should check. Possible forwarding is not included.
DMARC pass rateThe percentage of emails that passed DMARC evaluation.
Estimated serviceThe column for the sending service name. The current import does not set a value, so it shows "-". "Estimated confidence" in the detail area is the same.
Configured matchWhether the IP matches the own IPs or forwarding IPs you registered on the settings screen ("Own IP registered", "Forwarder IP registered", or "No match"). If you have registered nothing, every row reads "No match". A match does not automatically mean there is no issue if DMARC fails.

Recommended order

  1. Start with rows that have the highest count of items to check.
  2. For rows with no configured match, confirm whether the source is legitimate. If it is one of your servers, register it on the settings screen; if it is a legitimate forwarding server, register it with "Register as a forwarding server" (Chapter 3).
  3. If a row marked "Own IP registered" has a low DMARC pass rate, review SPF / DKIM / DMARC settings for that server.
  4. Select a row and open related record details to see the conclusion and recommended action.
  5. Export CSV when you need to share the source-IP review with your team.

CSV files are written in UTF-8 with a BOM, so Excel opens them directly. Column names are fixed in English.
