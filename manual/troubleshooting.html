トラブルシューティング

起動や取込で問題が発生した場合の対処方法をまとめます。ここに記載のない症状については サポート・FAQ もご確認ください。

起動関連

アプリが起動しない / 白い画面のまま

  • 原因候補: Microsoft Edge WebView2 Runtime が不足。
  • 対処: Microsoft 公式サイトから WebView2 Runtime（Evergreen Bootstrapper）を導入。Windows 11 は通常プリインストール済み。

レポート取込関連

分析できるレポートファイルが見つからないと表示される

  • 原因候補: フォルダ内に DMARC 集約レポート（XML / ZIP / GZ）が存在しない。別種のファイルを指定している。ファイルが破損している。
  • 対処: ZIP / GZ 添付ファイルをフォルダに保存し直して再試行。読み取れないレポートは分析の対象外になり、レコード一覧には表示されません。取込結果のレポート件数が想定より少ない場合は、対象ファイルを除外して再取込してください。

判定・reject 移行準備関連

設定画面に登録した自社 IP・転送サーバーが判定に反映されない

  • 原因候補: 登録を保存した後に、新しく分析していない。保存済みの記録が、登録する前の判定のまま残っている。IP アドレス範囲を、設定画面のヒントと同じ形式（例: 203.0.113.0/24）で入力していない（「/」のない単独の IP アドレスは、判定で無視されます。1 台だけを登録するときは 203.0.113.10/32 のように書きます）。
  • 対処: 保存した内容は、次の分析から反映されます（アプリの再起動は不要）。保存済みの記録は、「reject 移行準備」の「転送サーバーとして登録」「正当な送信元として登録」の操作で再判定でき、区分ごとの件数の変化が表示されます。「設定ファイルを使用できないため、再判定を中止しました」と表示された場合は、保存済みの記録は変更されていません。設定ファイルの形式を修正して、もう一度お試しください。

「reject 移行準備」が「判断材料が不足しています」になる

  • 原因候補: 分析期間（最新のレポートから遡って 90 日）にレポートがない、レポート提供元が 2 社未満、受信日数が 30 日未満、届いていない日がある、メッセージ総数が 100 件未満（いずれも運用目安。公式の根拠なし）。
  • 対処: 画面の推奨アクションに、不足している情報と確認方法が表示されます。詳しくは第 3 章をご覧ください。

「保存されていない情報があります」と表示される

  • 原因候補: 公開ポリシー（p・pct・adkim・aspf）や受信側の判定（disposition・reason）を保存する前に取り込んだレポートがある。
  • 対処: 「DMARC ローカル取込」または Microsoft 365 から、レポートを再取り込みします。

Microsoft 365 連携関連

Microsoft 365 に接続できない

  • 原因候補: テナント ID・クライアント ID の誤り、テナントの条件付きアクセスでブロック、権限の同意がまだ、ネットワーク未接続。
  • 対処: 設定画面でテナント ID とクライアント ID を確認し、「接続テスト」を実行します。管理者にアプリの同意可否を確認してください。組織アカウントでは管理者同意が必要な場合があります。

接続はできるがメールが取れない

  • 原因候補: 共有メールボックスへの読み取り権限（Mail.Read.Shared）が付与されていない、対象のメールボックスにレポートがない。
  • 対処: 別クライアントでメールの存在を確認してください。画面からの取得は、読み取りの権限だけを使います。

CSV エクスポート関連

Excel で開くと文字化け

  • 原因候補: Excel の既定エンコーディング。
  • 対処: 本ツールの CSV は UTF-8 BOM 付きで出力します。Excel 365 は通常そのまま読めます。古い Excel では「データの取得 > テキスト」で UTF-8 を指定してください。

データ保存先とリセット

本ツールはユーザーデータを %LocalAppData%\DmarcAnalysisAssistant 配下に保存します。設定画面の「保存済みDMARC解析データを削除」から、保存済みの DMARC 解析結果と処理済みマーカーを削除できます。この操作では、設定、同意情報、管理区分メモ、バウンス分析データは削除されません。

それでも解決しない場合

  • サポート・FAQ で該当する質問を検索
  • サポート（support@sumikkolab.com）へメールで連絡

Troubleshooting

Common issues and how to resolve them. If your issue is not listed here, see Support & FAQ.

Launch issues

The app does not start / stays on a blank screen

  • Likely cause: Microsoft Edge WebView2 Runtime is missing.
  • Fix: Install the WebView2 Runtime (Evergreen Bootstrapper) from Microsoft's official site. It is typically pre-installed on Windows 11.

Report import issues

"No analyzable report files were found"

  • Likely cause: The folder contains no DMARC aggregate reports (XML / ZIP / GZ), the wrong files were selected, or a file is corrupted.
  • Fix: Save ZIP / GZ attachments into the folder and retry. A report that cannot be read is not analyzed and does not appear in the DMARC Records list. If the report count in the import result is lower than expected, move the offending file aside and retry.

Classification and readiness for reject

Own IPs or forwarding servers registered on the settings screen are not reflected

  • Likely cause: No new analysis has run since you saved the registration, or saved records still carry the classification from before you registered. The IP address range may also not be in the format shown in the settings screen hint (for example 203.0.113.0/24): a single IP address without "/" is ignored in classification (to register one host, write it like 203.0.113.10/32).
  • Fix: Saved settings apply from the next analysis (no restart needed). You can re-evaluate saved records with "Register as a forwarding server" or "Register as a legitimate sender" in "Readiness for reject"; the change in counts per category is shown. If the screen says the re-evaluation was stopped because the settings file cannot be used, saved records were left unchanged. Fix the settings file format and try again.

"Readiness for reject" says "Not enough information to decide"

  • Likely cause: No reports in the analysis period (the 90 days up to the latest report), fewer than 2 report providers, reports on fewer than 30 days, days with no report, or fewer than 100 messages in total (all operational guidelines with no official basis).
  • Fix: The recommended actions on the screen show what is missing and how to check it. See Chapter 3 for details.

"Some information is not stored" appears

  • Likely cause: A report was imported before the published policy (p, pct, adkim, aspf) or the receiver's decision (disposition, reason) was stored.
  • Fix: Re-import the reports from "DMARC Local Import" or from Microsoft 365.

Microsoft 365 integration

Cannot connect to Microsoft 365

  • Likely cause: Wrong tenant ID or client ID, blocked by a conditional access policy, permission not consented, or no network.
  • Fix: Check the tenant ID and client ID on the settings screen and run the connection test. Ask your admin whether app consent is permitted; organizational accounts may require admin consent.

Connected, but no mail is retrieved

  • Likely cause: The read permission for the shared mailbox (Mail.Read.Shared) is not granted, or the target mailbox has no reports.
  • Fix: Verify the messages exist via another client. Fetching from the app screen uses only the read permission.

CSV export

Garbled characters in Excel

  • Likely cause: Excel default encoding.
  • Fix: Our CSV is UTF-8 with BOM. Excel 365 reads it as-is. In older Excel, use "Get Data > From Text" and specify UTF-8.

Data location and reset

User data is stored under %LocalAppData%\DmarcAnalysisAssistant. Open Settings and use "Delete stored DMARC analysis data" to delete saved DMARC analysis results and processed markers. This action does not delete settings, consent information, management notes, or bounce analysis data.
