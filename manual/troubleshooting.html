トラブルシューティング

起動や取込で問題が発生した場合の対処方法をまとめます。ここに記載のない症状については サポート・FAQ もご確認ください。

起動関連

アプリが起動しない / 白い画面のまま

  • 原因候補: Microsoft Edge WebView2 Runtime が不足。
  • 対処: Microsoft 公式サイトから WebView2 Runtime（Evergreen Bootstrapper）を導入。Windows 11 は通常プリインストール済み。

レポート取込関連

分析できるレポートファイルが見つからないと表示される

  • 原因候補: フォルダ内に DMARC 集約レポート（XML / ZIP / GZ）が存在しない。別種のファイルを指定している。読み取り権限のないフォルダと、16 階層を超えるサブフォルダは対象外です。
  • 対処: ZIP / GZ 添付ファイルをフォルダに保存し直して再試行してください。ファイルが破損しているときは、この表示ではなく、下記の「取り込めなかった項目があります」の表示になります。

「取り込めなかった項目があります」と表示される

取り込み結果欄に「取り込めなかった項目が N 件あります。」と表示され、その下に「ファイル名: 原因の文」の形で、取り込めなかった項目が最大 5 件まで表示されます。取り込めた項目は保存されています。1 件の失敗で、ほかのレポートの取り込みが中止されることはありません。ただし、データベースに保存できないときは、取り込み全体が中止されます。

  • 原因の文（分類）:
    • 「ファイルを読み取れませんでした」
    • 「zip / gz の展開に失敗しました」
    • 「XML を読み取れませんでした」
    • 「レコードを読み取れませんでした」
    • 「フォルダ内のファイルを一覧表示できませんでした」
    • 「データベースへの保存に失敗しました」
    • 「config.json を読み込めませんでした」
    • 「原因を特定できない失敗です」
  • 詳細: 原因の文の後ろに「（詳細: …）」が付く場合があります。詳細に、英語のメッセージがそのまま表示されることがあります。
  • 対処: 表示されたファイルを確認します。ファイルを再取得して、もう一度「分析を開始する」を押してください。

「すべて取り込めませんでした」「保存できるレコードがありませんでした」と表示される

  • 画面の文言: 「N 件のファイルを検出しましたが、すべて取り込めませんでした（失敗 N 件）。以下の原因を確認してください。」または「N 件のファイルを読み取りましたが、保存できるレコードがありませんでした。」
  • 対処: 前者は、表示された原因の文を上の項目の分類で確認します。後者は、ファイルが DMARC 集約レポートか確認してください。

「ほか N 件」と表示される

  • 意味: 取り込めなかった項目が 6 件以上あります。画面には先頭の 5 件だけ表示され、残りは「ほか N 件」と表示されます。
  • 対処: 表示された 5 件の原因を解消して、もう一度「分析を開始する」を押してください。残りの項目が、次の取り込みで表示されます。

データベースに関する原因の文が表示される

  • 「データベースが読み取り専用のため、保存できません」
  • 「データベースのファイルが SQLite の形式ではありません。ファイルは変更していません」
  • 「データベースが他のプロセスに使用されています。使用を終えてから、もう一度実行してください」
  • 「データベースの構造が合っていません（列が足りません）。アプリを再起動して、データベースを更新してください」
  • 「データベースを開けないか、保存できません。保存先を確認してください」

各文に、次の操作が書かれています。文の指示に従ってください。

「設定ファイルに警告があります」と表示される

  • 意味: 設定ファイル（config.json）の一部の値が使えません。取り込みは続行され、警告に値は表示されません。たとえば、IP アドレス範囲の接頭辞が長すぎる、同じキーが重複している（後の値を使います）、値を範囲として読めない、などです。
  • 対処: 設定ファイルの該当項目を修正してください。設定画面に登録した IP アドレス範囲の形式は、設定画面のヒントに合わせます。

「設定ファイルの問題（…）のため、新しいレポートだけ保存し、既存のレポートは置き換えません」と表示される

  • 意味: 設定ファイルを使用できないため、新しいレポートだけを保存しました。保存済みのレポートは置き換えていません。新しいレポートは、登録した IP アドレス範囲を使わない設定で分類されています。
  • 原因の例: 「設定ファイルを読み取れません」「設定ファイルが空です」「設定ファイルが正しい JSON ではありません」「設定ファイルの最上位がオブジェクトではありません」「設定ファイルの項目の形式が正しくありません（文字列の一覧が必要です）」。
  • 対処: 設定ファイルを修正します。そのあと、「reject 移行準備」の「転送サーバーとして登録」「正当な送信元として登録」の操作で再判定すると、分類を修正できます。

「置き換えなかったレポート N 件」と表示される

  • 意味: 設定ファイルの問題があるとき、同じレポートがすでに保存されているため、保存済みの内容を置き換えませんでした。
  • 項目ごとの原因の文: 「同じレポートがすでに保存されていて、再送に不正なレコードがあるため、置き換えませんでした。保存済みのデータは変更していません」。または「すべてのレコードが不正なため、レポートを保存しませんでした」。
  • 対処: 設定ファイルの問題が原因のときは、設定ファイルを修正して、もう一度取り込みます。再送に不正なレコードがあるときは、保存済みのデータは変更されていません。レポートの送信元に、正しいレポートの再送を依頼してください。

「重複したレポート N 件を除外しました」と表示される

  • 意味: 同じレポートが、同名の ZIP と XML などで重複していたため、1 回だけ数えました。失敗ではありません。

判定・reject 移行準備関連

設定画面に登録した自社 IP・転送サーバーが判定に反映されない

  • 原因候補: 登録を保存した後に、新しく分析していない。保存済みの記録が、登録する前の判定のまま残っている。IP アドレス範囲を、設定画面のヒントと同じ形式（例: 203.0.113.0/24）で入力していない（「/」のない単独の IP アドレスは、判定で無視されます。1 台だけを登録するときは 203.0.113.10/32 のように書きます）。
  • 対処: 保存した内容は、次の分析から反映されます（アプリの再起動は不要）。保存済みの記録は、「reject 移行準備」の「転送サーバーとして登録」「正当な送信元として登録」の操作で再判定でき、区分ごとの件数の変化が表示されます。「設定ファイルを使用できないため、再判定を中止しました」と表示された場合は、保存済みの記録は変更されていません。設定ファイルの形式を修正して、もう一度お試しください。

「reject 移行準備」が「判断材料が不足しています」になる

  • 原因候補: 分析期間（最新のレポートから遡って 90 日）にレポートがない、レポート提供元が 2 社未満、受信日数が 30 日未満、届いていない日がある、メッセージ総数が 100 件未満（いずれも運用目安。公式の根拠なし）。
  • 対処: 画面の推奨アクションに、不足している情報と確認方法が表示されます。詳しくは第 3 章をご覧ください。

「保存されていない情報があります」と表示される

  • 原因候補: 公開ポリシー（p・pct・adkim・aspf）や受信側の判定（disposition・reason）を保存する前に取り込んだレポートがある。
  • 対処: 「DMARC ローカル取込」または Microsoft 365 から、レポートを再取り込みします。

Microsoft 365 連携関連

Microsoft 365 に接続できない

  • 原因候補: テナント ID・クライアント ID の誤り、テナントの条件付きアクセスでブロック、権限の同意がまだ、ネットワーク未接続。
  • 対処: 設定画面でテナント ID とクライアント ID を確認し、「接続テスト」を実行します。管理者にアプリの同意可否を確認してください。組織アカウントでは管理者同意が必要な場合があります。

接続はできるがメールが取れない

  • 原因候補: 共有メールボックスへの読み取り権限（Mail.Read.Shared）が付与されていない、対象のメールボックスにレポートがない。
  • 対処: 別クライアントでメールの存在を確認してください。画面からの取得は、読み取りの権限だけを使います。

「取り込めなかったものがあるメール N 件は、処理済みにしません」と表示される

  • 意味: 取得したメールの添付ファイルに、取り込めなかった項目がありました。そのメールは処理済みになりません。次回の取り込みで、もう一度処理します。
  • 対処: 取り込めなかった原因は、上記の「取り込めなかった項目があります」の項目で確認してください。

CSV エクスポート関連

Excel で開くと文字化け

  • 原因候補: Excel の既定エンコーディング。
  • 対処: 本ツールの CSV は UTF-8 BOM 付きで出力します。Excel 365 は通常そのまま読めます。古い Excel では「データの取得 > テキスト」で UTF-8 を指定してください。

診断モード（任意）

取り込みの原因が上の項目で分からないときに、サポートへ送る診断ファイルを出力できます。診断モードは任意の機能です。設定画面の「診断モード」で切り替えます。

  • 既定: オフです。アプリを起動するたびにオフになります。
  • オンにするとき: 診断ファイルに「含まれるもの」「含まれないもの」と「常に保存される最小のエラー記録」が画面に表示されます。「オンにする」を選んだときだけ、オンになります。
  • 含まれるもの: 値は、固定の分類・数値・はい/いいえだけです。自由な文字列は含まれません。エラーと処理段階の分類、件数の区分、ファイルの特徴の区分、アプリのバージョン、表示言語などが含まれます。
  • 含まれないもの: ドメイン、IP アドレス、メールアドレス、ファイル名、フォルダのパス、レポートの値、例外のメッセージ、設定の値、データベースの内容。
  • 常に保存される最小のエラー記録: 診断モードがオフのときも、未処理の例外・処理されずに無視された例外・メモリ不足・起動の失敗・前回の異常終了を、分類だけで最大 7 日間保存します。診断ファイルには、これも含まれます。
  • 出力と送付: 診断モードをオフにするとき、診断データがあれば、「診断ファイルを出力して削除」「削除する」「削除せずにオフにする」「キャンセル」から選べます。診断ファイルは、選んだ場所に zip ファイルとして出力されます。アプリが診断ファイルを送信することはありません。内容を確認したうえで、利用者の判断でサポート（support@sumikkolab.com）へ送付してください。
  • 削除: 「診断ファイルを出力して削除」を選ぶと、出力できたときだけ、アプリ内の診断データを削除します。「削除せずにオフにする」を選んだ場合、診断データは最大 7 日間残ります。

データ保存先とリセット

本ツールはユーザーデータを %LocalAppData%\DmarcAnalysisAssistant 配下に保存します。設定画面の「保存済みDMARC解析データを削除」から、保存済みの DMARC 解析結果と処理済みマーカーを削除できます。この操作では、設定、同意情報、管理区分メモ、バウンス分析データは削除されません。診断データも、この操作では削除されません。診断データは、診断モードをオフにするときに削除を選ぶと削除されます。選ばなかった場合は、最大 7 日間残ります。

それでも解決しない場合

  • サポート・FAQ で該当する質問を検索
  • サポート（support@sumikkolab.com）へメールで連絡

Troubleshooting

Common issues and how to resolve them. If your issue is not listed here, see Support & FAQ.

Launch issues

The app does not start / stays on a blank screen

  • Likely cause: Microsoft Edge WebView2 Runtime is missing.
  • Fix: Install the WebView2 Runtime (Evergreen Bootstrapper) from Microsoft's official site. It is typically pre-installed on Windows 11.

Report import issues

"No analyzable report files were found"

  • Likely cause: The folder contains no DMARC aggregate reports (XML / ZIP / GZ), or the wrong files were selected. Folders you do not have permission to read, and subfolders nested more than 16 levels deep, are skipped.
  • Fix: Save ZIP / GZ attachments into the folder and retry. If a file is corrupted, you see "{N} item(s) could not be imported" (below) instead of this message.

"{N} item(s) could not be imported"

The import result shows "{N} item(s) could not be imported." Below it, up to 5 items appear in the form "file name: cause". The items that could be imported are saved. One failure does not stop the import of the other reports. However, if the database cannot be saved to, the whole import stops.

  • Cause text (class):
    • "The file could not be read"
    • "The zip / gz file could not be extracted"
    • "The XML could not be read"
    • "A record could not be read"
    • "The files in the folder could not be listed"
    • "Saving to the database failed"
    • "config.json could not be loaded"
    • "The cause could not be identified"
  • Details: "(details: ...)" may follow the cause text. The details can be an English message as is.
  • Fix: Check the file shown, download it again, and select "Start analysis" again.

"none could be imported" or "they contained no records to save"

  • On screen: "Found N file(s), but none could be imported (N failure(s)). Check the causes below." or "N file(s) were read, but they contained no records to save."
  • Fix: For the first message, check the cause text against the classes in the item above. For the second, check that the files are DMARC aggregate reports.

"and N more"

  • Meaning: Six or more items could not be imported. The screen shows the first 5 only; the rest appear as "and N more".
  • Fix: Resolve the 5 causes shown and select "Start analysis" again. The next import shows the remaining items.

A cause text about the database appears

  • "The database is read-only, so nothing can be saved"
  • "The database file is not in the SQLite format. The file was not changed"
  • "The database is in use by another process. Close it, then run the import again"
  • "The structure of the database does not match (columns are missing). Restart the app to update the database"
  • "The database cannot be opened or saved. Check the location"

Each text states the next step. Follow it.

"The configuration file has a warning"

  • Meaning: Some values in the configuration file (config.json) cannot be used. The import continues, and the warning does not show the value. Examples: an IP address range prefix is too long, the same key appears twice (the later value is used), or a value cannot be read as a range.
  • Fix: Correct the item in the configuration file. Write the IP address ranges in the format shown in the settings screen hint.

"Because of a problem with the configuration file (...), only new reports are saved and existing reports are not replaced"

  • Meaning: The configuration file cannot be used, so only new reports were saved. Reports that were already saved were not replaced. New reports are classified without your registered IP address ranges.
  • Example causes: "The configuration file cannot be read", "The configuration file is empty", "The configuration file is not valid JSON", "The top level of the configuration file is not an object", "The format of a setting in the configuration file is not valid (a list of strings is required)".
  • Fix: Fix the configuration file. Then re-evaluate with "Register as a forwarding server" or "Register as a legitimate sender" in "Readiness for reject" to correct the classification.

"N existing report(s) were not replaced"

  • Meaning: When there is a problem with the configuration file, reports that were already saved were not replaced with the same reports.
  • Cause text per item: "The same report is already stored and the resend has an invalid record, so it was not replaced. The stored data is unchanged", or "Every record is invalid, so the report was not saved".
  • Fix: If the cause is the configuration file, fix it and import again. If the resend has an invalid record, the stored data is unchanged. Ask the sender of the report to send a correct report again.

"N duplicate report(s) were excluded"

  • Meaning: The same report appeared twice, for example as a ZIP and an XML with the same name, so it was counted once. This is not a failure.

Classification and readiness for reject

Own IPs or forwarding servers registered on the settings screen are not reflected

  • Likely cause: No new analysis has run since you saved the registration, or saved records still carry the classification from before you registered. The IP address range may also not be in the format shown in the settings screen hint (for example 203.0.113.0/24): a single IP address without "/" is ignored in classification (to register one host, write it like 203.0.113.10/32).
  • Fix: Saved settings apply from the next analysis (no restart needed). You can re-evaluate saved records with "Register as a forwarding server" or "Register as a legitimate sender" in "Readiness for reject"; the change in counts per category is shown. If the screen says the re-evaluation was stopped because the settings file cannot be used, saved records were left unchanged. Fix the settings file format and try again.

"Readiness for reject" says "Not enough information to decide"

  • Likely cause: No reports in the analysis period (the 90 days up to the latest report), fewer than 2 report providers, reports on fewer than 30 days, days with no report, or fewer than 100 messages in total (all operational guidelines with no official basis).
  • Fix: The recommended actions on the screen show what is missing and how to check it. See Chapter 3 for details.

"Some information is not stored" appears

  • Likely cause: A report was imported before the published policy (p, pct, adkim, aspf) or the receiver's decision (disposition, reason) was stored.
  • Fix: Re-import the reports from "DMARC Local Import" or from Microsoft 365.

Microsoft 365 integration

Cannot connect to Microsoft 365

  • Likely cause: Wrong tenant ID or client ID, blocked by a conditional access policy, permission not consented, or no network.
  • Fix: Check the tenant ID and client ID on the settings screen and run the connection test. Ask your admin whether app consent is permitted; organizational accounts may require admin consent.

Connected, but no mail is retrieved

  • Likely cause: The read permission for the shared mailbox (Mail.Read.Shared) is not granted, or the target mailbox has no reports.
  • Fix: Verify the messages exist via another client. Fetching from the app screen uses only the read permission.

"{N} email(s) with something that could not be imported are not marked as processed"

  • Meaning: An item in the attachments of a fetched email could not be imported. The email is not marked as processed. The next import processes the email again.
  • Fix: Check the cause in the item "{N} item(s) could not be imported" above.

CSV export

Garbled characters in Excel

  • Likely cause: Excel default encoding.
  • Fix: Our CSV is UTF-8 with BOM. Excel 365 reads it as-is. In older Excel, use "Get Data > From Text" and specify UTF-8.

Diagnostic mode (optional)

If the items above do not explain an import problem, you can export a diagnostic file to send to support. The diagnostic mode is optional. Turn it on or off with the "Diagnostic mode" setting on the settings screen.

  • Default: Off. It turns off every time the app starts.
  • When you turn it on: The screen shows what the diagnostic file includes, what it does not include, and the minimal error records that are always stored. The mode turns on only when you select "Turn on".
  • Included: Every value is a fixed class, a number, or yes/no. No free text is included. It contains classes of errors and processing stages, number classes, classes of file features, the app version, the display language, and similar items.
  • Not included: Domains, IP addresses, email addresses, file names, folder paths, report values, exception messages, setting values, and database contents.
  • Minimal error records that are always stored: Even when the mode is off, the app stores unhandled exceptions, ignored exceptions, out-of-memory errors, startup failures, and a previous abnormal exit, as classes only, for up to 7 days. The diagnostic file includes them.
  • Export and sending: When you turn the mode off and diagnostic data exists, you can choose "Export the diagnostic file and delete the data", "Delete the data", "Turn off and keep the data", or "Cancel". The file is exported as a zip file to the location you choose. The app never sends the diagnostic file. Check its content, then send it to support (support@sumikkolab.com) at your own discretion.
  • Deletion: If you choose "Export the diagnostic file and delete the data", the app deletes its diagnostic data only after the export succeeds. If you choose "Turn off and keep the data", the data is kept for up to 7 days.

Data location and reset

User data is stored under %LocalAppData%\DmarcAnalysisAssistant. Open Settings and use "Delete stored DMARC analysis data" to delete saved DMARC analysis results and processed markers. This action does not delete settings, consent information, management notes, or bounce analysis data. It does not delete diagnostic data either. Diagnostic data is deleted if you choose to delete it when you turn the diagnostic mode off. If you do not, it is kept for up to 7 days.
