DMARC 分析支援ツール マニュアル

このマニュアルは DMARC 分析支援ツール 1.1.1.0 の操作を章ごとに説明します。左のメニューから章を選択してください。

「このドメインを p=reject に上げてよいか」を判断したいとき

  1. 集約レポートを取り込みます（第 1 章）。
  2. 左のメニューの「reject 移行準備」を開きます。画面の最上部に、判定（移行可能 / 条件つき（要対応あり） / 準備未完了 / 判断材料が不足しています）と、通過率のゲージ、推奨アクションが表示されます。
  3. 判定ごとの次の一手を確認します（第 3 章）。「判断材料が不足しています」なら取り込みを続け、「準備未完了」なら失敗の原因を解消し、「条件つき」なら quarantine で運用しながら残りの点を解消し、「移行可能」なら reject への変更を検討します。
  4. 失敗の原因は、「reject にした場合の影響」の内訳（自社送信元の認証失敗・判定保留・なりすまし疑い・転送経由の可能性）で見分けます。転送が原因なら、通過率を「全体」と「転送経由の可能性を除く」で比べ、正当な転送サーバーを登録します。
通過率の帯の値（75%・90%・99%）は運用目安（公式の根拠なし）です。実際に拒否するかどうかは、受信側の判断によります。

このツールの流れ

  1. 同意 — 初回起動時に利用規約・免責事項を確認し、同意する
  2. 取込 — フォルダまたは Microsoft 365 の共有メールボックスから DMARC レポート（XML / ZIP / GZ）を取得
  3. 判定 — 各レコードを、正常・なりすまし疑い・自社送信元の認証失敗・転送経由の可能性などの区分に判定（第 4 章）
  4. 確認 — 「reject 移行準備」、ダッシュボード、レコード一覧、送信元サーバー別集計で状況を把握
  5. エクスポート — 技術レポート・経営レポート（PDF）、Excel、CSV で出力

DMARC Analysis Assistant Manual

This manual walks through DMARC Analysis Assistant 1.1.1.0 chapter by chapter. Choose a chapter from the menu on the left.

When you want to know whether this domain can move to p=reject

  1. Import your aggregate reports (Chapter 1).
  2. Open "Readiness for reject" in the left menu. The top of the screen shows the verdict (Ready to move / Conditional (action needed) / Not ready / Not enough information to decide), the pass-rate gauge, and recommended actions.
  3. Check the next step for your verdict (Chapter 3). For "Not enough information to decide", keep importing; for "Not ready", resolve the causes of the failures; for "Conditional", run with quarantine while resolving the remaining points; for "Ready to move", consider changing to reject.
  4. Tell the causes apart in the breakdown under "Impact of moving to reject" (authentication failures from your own senders, pending review, possible spoofing, possible forwarding). If forwarding is the cause, compare the pass rate "All messages" with "Excluding possible forwarding", and register legitimate forwarding servers.
The band values (75%, 90%, 99%) are operational guidelines (no official basis). Whether a receiver actually rejects mail is up to the receiver.

Workflow

  1. Consent — Review the Terms of Use & Disclaimer on first launch and accept
  2. Import — Load DMARC reports (XML / ZIP / GZ) from a folder or from a Microsoft 365 shared mailbox
  3. Classify — Each record is classed as OK, Spoofing suspected, Authentication failures from your own senders, Possible forwarding, and so on (Chapter 4)
  4. Review — Use "Readiness for reject", the dashboard, the DMARC Records list, and the sending-server summary
  5. Export — Technical and executive PDF reports, Excel, and CSV

Scope of this manual
