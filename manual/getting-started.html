はじめに

本章では、DMARC 分析支援ツールのインストールから初回レポート取込までを説明します。取り込んだ後は、「reject 移行準備」で p=reject に上げてよいかを確認します（第 3 章）。

このツールができること（再掲）

  • DMARC 集約レポート（XML・ZIP・GZ）を取り込み、このドメインを p=reject に上げてよいかを判断できるように示す
  • 各レコードを、正常・なりすまし疑い・自社送信元の認証失敗・転送経由の可能性などに判定（ルールベース・決定論）
  • ダッシュボード、レコード一覧、送信元サーバー別集計で状況を把握
  • DMARC とは別の機能として、バウンスメールの分析（Microsoft 365 または EML フォルダから取り込み）
  • 技術レポート・経営レポート（PDF）、Excel、CSV で出力

システム要件

  • Windows 10 / 11（64-bit）
  • .NET 10（Store 版に同梱）
  • Microsoft Edge WebView2 Runtime（Windows 11 は通常プリインストール）
  • Microsoft 365 連携を使う場合のみ: Microsoft 365 アカウントとインターネット接続

インストール

  1. Microsoft Store で「DMARC 分析支援ツール」を検索してインストールします。
  2. スタートメニューからアプリを起動します。
  3. 初回起動時に「利用規約・免責事項」画面が表示されます。

初回同意

  1. 画面に表示される利用規約および免責事項をご確認ください。
  2. 画面下部の「利用規約と免責事項を確認し、同意します。」にチェックを入れます。
  3. 「同意してはじめる」ボタンをクリックすると本体 UI に進みます。
  4. 同意しない場合は「同意しない（アプリを終了する）」でアプリが終了します。
規約は 利用規約・免責事項 ページに掲載しています。規約が改訂された場合は、改訂版への同意が必要になります。

DMARC レポートの準備

DMARC レポートを取得するには、自社の DNS TXT レコードに DMARC ポリシーを設定し、rua= タグでレポート受信用メールアドレスを指定しておく必要があります。

例: v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com

受信側の事業者から届いた集約レポート（ZIP または GZ 添付）をフォルダに保存してください。

初回取込

  1. 最初の画面で「レポートファイルから確認する」を選ぶか、左のメニューの「DMARC ローカル取込」を開きます。
  2. 「フォルダを選択」で、DMARC レポートが保存されているフォルダを指定します。
  3. 「分析を開始する」を押すと、XML / ZIP / GZ を展開して解析が始まります。
  4. 完了後、ダッシュボードに集計結果が表示されます。左のメニューの「reject 移行準備」で、判定と次の一手を確認します。

同じレポートをもう一度取り込むと、保存済みの内容が最新の取り込み結果に置き換わります。

設定画面で登録しておくこと

設定画面の「自社メールサーバーの IP アドレス」と「既知の転送サーバー」に IP アドレス範囲（例: 203.0.113.0/24）を登録すると、その IP からの認証失敗は、それぞれ「自社送信元の認証失敗」「転送経由の可能性」に分類されます。保存した内容は、次の分析から反映されます（第 4 章）。

Microsoft 365 の共有メールボックスから取得する場合（任意）

Microsoft 365 の共有メールボックスから DMARC レポートを直接取り込むこともできます。この機能は任意で、設定画面でテナント ID とクライアント ID を設定します（Azure Portal でのアプリ登録が必要です）。画面からの取得では、読み取りの権限（Mail.Read.Shared）だけを使い、メールの削除・移動・既読化・送信は行いません。コマンドライン（CLI）には、取得後にメールを削除するモードがあります。画面は、このモードを使いません。

Getting Started

This chapter walks through installing the DMARC Analysis Assistant, giving first-launch consent, and importing your first DMARC reports. After importing, use "Readiness for reject" to check whether you can move to p=reject (Chapter 3).

What this tool does (recap)

  • Imports DMARC aggregate reports (XML, ZIP, or GZ) and shows whether this domain can move to p=reject
  • Classifies each record as OK, Spoofing suspected, Authentication failures from your own senders, Possible forwarding, and so on, with a deterministic rule-based engine
  • Shows the status on the dashboard, the Findings list, and the sending-server summary
  • As a separate feature from DMARC, analyzes bounce messages (imported from Microsoft 365 or a local EML folder)
  • Exports technical and executive PDF reports, Excel, and CSV

System requirements

  • Windows 10 / 11 (64-bit)
  • .NET 10 (included with the Store package)
  • Microsoft Edge WebView2 Runtime (pre-installed on Windows 11)
  • Only for Microsoft 365 integration: a Microsoft 365 account and internet access

Installation

  1. Search for "DMARC Analysis Assistant" in Microsoft Store and install.
  2. Launch the app from the Start menu.
  3. The "Terms of Use & Disclaimer" screen appears on first launch.

First-launch consent

  1. Review the Terms of Use and Disclaimer displayed on screen.
  2. Check the agreement box at the bottom (you have read and agree to the Terms of Use and Disclaimer).
  3. Click the agree button to proceed to the main UI.
  4. If you do not agree, choose the decline option and the app will close.
The terms are published on the Terms of Use & Disclaimer page. If the terms are revised, agreement to the revised version will be required.

Preparing DMARC reports

To receive DMARC reports, publish a DMARC policy in your DNS TXT record and specify a mailbox with the rua= tag.

Example: v=DMARC1; p=none; rua=mailto:dmarc-reports@example.com

Save the aggregate reports (ZIP or GZ attachments) sent by receiving mail providers to a folder.

First import

  1. On the first screen choose the option to check from report files, or open "Local DMARC import" in the left menu.
  2. Select the folder that contains the DMARC reports.
  3. Start the analysis — XML / ZIP / GZ files are expanded and parsed.
  4. When it completes, the results appear on the dashboard. Open "Readiness for reject" in the left menu to see the verdict and the next step.

If you import the same report again, the saved content is replaced with the latest import result.

What to register on the settings screen

If you register IP address ranges (for example 203.0.113.0/24) under "IP addresses of your own mail servers" and "Known forwarding servers" on the settings screen, authentication failures from those IPs are classed as "Authentication failures from your own senders" and "Possible forwarding" respectively. Saved settings apply from the next analysis (Chapter 4).

Importing from a Microsoft 365 shared mailbox (optional)

You can also import DMARC reports directly from a Microsoft 365 shared mailbox. This feature is optional; you set the tenant ID and client ID on the settings screen (an app registration in the Azure Portal is required). Fetching from the app screen uses only the read permission (Mail.Read.Shared) and never deletes, moves, marks as read, or sends mail. The command-line interface (CLI) has a mode that deletes mail after fetching it; the app screen does not use this mode.
