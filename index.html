このツールを一言で

これは何か
DMARC 集約レポート（RUA）とバウンスメールを取り込み、「このドメインを p=reject に上げてよいか」を判断できるように示す Windows デスクトップアプリ。
誰向けか
自社ドメインを持ち、DMARC ポリシーを none から quarantine、reject へ強化したい情シス・運用担当者。
何ができる
reject 移行準備の判定（4 値）・通過率のゲージ・推奨アクション・reject にした場合に拒否される見込み・判定の根拠・転送の影響。レコードの分類、送信元サーバー別とドメイン別の集計、PDF・Excel・CSV の出力。DMARC とは別の機能として、バウンスメールの分析。
何をしない
解析結果を外部の AI やクラウドの解析サービスに送らない。画面からの Microsoft 365 の取得では、メールの削除・移動・既読化・送信をしない。DNS を変更しない。

こんな課題を解決します

このドメインを p=reject に上げてよいか分からないとき

「reject 移行準備」の画面の最上部に、判定（移行可能 / 条件つき（要対応あり） / 準備未完了 / 判断材料が不足しています）と、通過率のゲージが表示されます。判定ごとの次の一手は、推奨アクションに表示されます。

p=reject に上げられないとき、何が原因か知りたい

「reject にした場合の影響」で、拒否される見込みの件数を、自社送信元の認証失敗・判定保留・なりすまし疑い・転送経由の可能性の内訳で確認できます。見込みは、最小（なりすまし疑いだけ）から最大（DMARC に失敗した全件）の範囲で示されます。

何をすればよいか知りたいとき

推奨アクションに、たとえば「自社送信元の認証失敗を修正する」「DKIM 署名を設定する」「公開ポリシーを quarantine に変更する」などが、判定と矛盾しない形で表示されます。reject への変更を促すのは、「移行可能」のときだけです。

転送されたメールの DMARC 失敗を、どう扱えばよいか判断したいとき

通過率を「全体」と「転送経由の可能性を除く」で並べ、除いた件数を併記します。失敗した転送の送信元の一覧から、正当な転送サーバーを「転送サーバーとして登録」でき、次回から転送として扱われます。「全体」の値は隠しません。

自社のメールサーバーが DMARC に失敗していないか知りたいとき

設定画面に自社メールサーバーの IP 範囲を登録すると、その IP からの認証失敗は「自社送信元の認証失敗」に分類されます。登録した内容は、次の分析から判定に使われ、メールボックス取り込みと CLI にも同じ設定が使われます。

送信元 IP が多く、どこから確認すべきか分からないとき

送信元サーバー別集計が、送信元 IP ごとにメール数・DMARC 成功率・設定照合をまとめます。問題が多い送信元から順に確認できます。

DMARC レポートの XML をどう読めばいいか分からないとき

DMARC 集約レポート（XML / ZIP / GZ）をフォルダまたは Microsoft 365 の共有メールボックスから取り込むと、送信元 IP・SPF/DKIM の結果・件数を読み取って、区分ごとに集計します。

複数ドメインを管理対象と監視対象に分けて整理したいとき

観測されたドメインごとに、管理区分（自社管理 / 監視のみ / 外部）・表示名・メモを付けられます。これらは運用メモで、分類や集計の結果には影響しません。

分析結果をレポートや Excel にしたいとき

技術レポートと経営レポートの 2 種類の PDF と、Excel・CSV を出力できます。CSV はレコード一覧（20 列）と送信元サーバー一覧（22 列）で、UTF-8（BOM 付き）です。列名はマニュアル第 5 章に掲載しています。

レポートを外部の解析サービスに出さずに解析したいとき

解析結果は PC 内に保存し、外部の AI やクラウドの解析サービスには送りません。Microsoft 365 への接続は、利用者が設定した場合に限ります。

判定・分類は機械判定で、すべての事例を正確に分けるとは限りません。実際の被害の有無や攻撃者の意図は示しません。最終的な判断は利用者の責任で行ってください。

DMARC レポート、本当に読めていますか？

DMARC 集約レポート（RUA）は XML で届き、送信元 IP、認証結果（SPF/DKIM）、件数が並ぶだけ。パッと見ても「p=reject に上げてよいのか」「どれが自社の送信元の認証失敗で、どれが転送で、どれがなりすましの疑いなのか」が分かりません。

本ツールは、取り込んだレポートをもとに、「上げてよいか」の判定と「何が原因で、何をすればよいか」を表示します。

「reject 移行準備」の見方

通過率の帯の値（75%・90%・99%）は、運用目安（公式の根拠なし）です。

判定意味次の一手
移行可能通過率が 99% 以上の帯で、自社送信元の認証失敗と判定保留がなく、ほかの条件もそろっている公開ポリシーが quarantine なら、reject への変更を検討します
条件つき（要対応あり）通過率は 90% 以上だが、確認が必要な点が残っているquarantine で運用しながら、原因を解消します
準備未完了通過率が 90% 未満先に失敗の原因を解消します（75% 未満は、送信元の洗い出しを優先）
判断材料が不足していますレポートの提供元・日数・件数が足りない、または欠けた日がある不足している情報と確認方法を、推奨アクションで確認します

画面には、このほか、拒否される見込みの内訳、判定の根拠（公式の根拠がある項目と、運用目安を区別。出典つき）、転送の影響（全体と、転送経由の可能性を除く値）が表示されます。詳しくはマニュアル第 3 章をご覧ください。

ダッシュボードで分かること

状態の 1 行
なりすましの疑いがあれば「外部から自社ドメインを装ったメールが検出されています」、自社送信元の認証失敗があれば「自社メールサーバーの認証設定に不備が見つかっています」、どちらも無ければ「メールセキュリティは正常です。問題は検出されていません。」と表示されます。
次にやること
該当する区分があれば、件数とともに、確認すべきことが表示されます。
区分ごとの件数
正常 / なりすまし疑い / 自社送信元の認証失敗 / 転送経由の可能性 / 判定保留。
ドメイン別サマリ
ドメインごとに、メール数・なりすまし疑い・DMARC 成功率を表で表示します。表示するドメインを 1 つ選ぶと、ダッシュボード全体をそのドメインに絞り込めます。

分類の条件

正常

DMARC が pass している。対応不要。

自社送信元の認証失敗

DMARC が fail し、送信元 IP が、設定画面に登録した自社メールサーバーの IP 範囲に含まれる。

転送経由の可能性

DMARC が fail し、送信元 IP が登録した転送サーバーの IP 範囲に含まれるか、受信側が trusted_forwarder または mailing_list と報告している。

なりすまし疑い

DMARC が fail し、上記のどれにも当てはまらない。

判定保留

DMARC が fail し、上記のどれにも当てはまらず、既知の送信サービスとして照合されたもの。現在の設定画面には登録の項目がないため、通常は付きません。

分類はルールベースで判定します。AI 推論やクラウド解析は使用しません。判定条件の詳細はマニュアル第 4 章をご覧ください。

主な機能

reject 移行準備

判定、通過率のゲージ、推奨アクション、拒否される見込み、判定の根拠、転送の影響、転送サーバーの登録。

DMARC 集約レポート解析

ZIP / GZ / XML の各形式に対応。送信元 IP・認証結果・件数を取得して判定します。

バウンスメール分析

Microsoft 365 または EML フォルダからバウンスメールを取り込み、分類ごとの次の対応と、検知・分類の根拠を表示します。DMARC の分類とは別の機能です。

送信元サーバー別集計と出力

送信元 IP ごとにメール数、DMARC 成功率、設定照合をまとめます。PDF（技術・経営）、Excel、CSV で出力できます。

プライバシー: 解析結果は PC 内に保存し、外部の AI やクラウドの解析サービスには送りません。Microsoft 365 への接続は、利用者が設定した場合に限ります。

Microsoft 365 の権限: 画面からの取得では、共有メールボックスの読み取り権限（Mail.Read.Shared）だけを使い、メールの削除・移動・既読化・送信は行いません。コマンドライン（CLI）には、取得後にメールを削除するモードがあります。

At a glance

What it is
A Windows desktop app that imports DMARC aggregate reports (RUA) and bounce messages, and shows whether a domain can move to p=reject.
Who it is for
IT / operations staff who own mail domains and want to strengthen the DMARC policy from none to quarantine to reject.
What it does
A readiness verdict (four values), a pass-rate gauge, recommended actions, expected rejections if you move to reject, the basis for the decision, and the impact of forwarding. Record classification, summaries by sending server and by domain, and PDF / Excel / CSV export. Bounce message analysis is a separate feature.
What it doesn't do
It does not send analysis results to external AI or cloud analysis services. Fetching from the app screen never deletes, moves, marks as read, or sends Microsoft 365 mail. It never changes DNS.

Problems this solves

I am not sure whether this domain can move to p=reject

The top of the "Readiness for reject" screen shows a verdict (Ready to move / Conditional (action needed) / Not ready / Not enough information to decide) and a pass-rate gauge. The recommended actions show the next step for that verdict.

The domain is not ready for reject — what is causing the failures?

"Impact of moving to reject" breaks the expected rejections down into authentication failures from your own senders, pending review, spoofing suspected, and possible forwarding. The outlook is a range, from the minimum (only suspected spoofing) to the maximum (all messages that fail DMARC).

What should I do next?

The recommended actions show steps such as fixing authentication failures from your own senders, setting up DKIM signing, or changing the published policy to quarantine, consistent with the verdict. The screen recommends changing to reject only when the verdict is "Ready to move".

How should I treat DMARC failures from forwarded mail?

The pass rate is shown two ways, for all messages and excluding possible forwarding, with the number of excluded messages. From the list of failing forwarding sources you can register a legitimate forwarding server, and it is treated as forwarding from the next analysis. The "all messages" value is never hidden.

Are my own mail servers failing DMARC?

If you register the IP ranges of your own mail servers on the settings screen, failures from those IPs are classed as "Authentication failures from your own senders". What you register is used from the next analysis, and mailbox import and the CLI use the same settings.

Which source IPs should I check first?

The sending server summary groups results by source IP, with mail volume, DMARC pass rate, and whether each IP matches what you registered. You can start with the sources that have the most problems.

How do I read a DMARC aggregate report in XML?

Import DMARC aggregate reports (XML / ZIP / GZ) from a folder or a Microsoft 365 shared mailbox, and the tool reads the source IPs, SPF/DKIM results, and counts and totals them by category.

How do I organize DMARC across multiple domains?

For each observed domain you can add a management tag (Managed / Monitored / External), a display name, and a note. These are operational notes and do not affect classification or totals.

Can I get the results as reports or in Excel?

Export two PDF reports (technical and executive), plus Excel and CSV. The CSV files are the record list (20 columns) and the sending server list (22 columns), in UTF-8 with a BOM. The column names are listed in Chapter 5 of the manual.

Can I analyze DMARC reports without sending them to an analysis service?

Analysis results are stored on your PC and are not sent to external AI or cloud analysis services. Microsoft 365 connections are made only when you configure them.

Verdicts and classifications are machine-produced and may not sort every entry correctly. They do not show whether harm occurred or what an attacker intended. The final judgment rests with you.

Can you actually read your DMARC reports?

DMARC aggregate reports (RUA) arrive as XML — just source IPs, SPF/DKIM results, and counts. At a glance it is impossible to tell whether it is safe to move to p=reject, or which rows are authentication failures from your own senders, which are forwarding, and which look like spoofing.

This tool uses the reports you import to show whether it is safe to move and what is causing the failures and what to do.

How to read "Readiness for reject"

The band values (75%, 90%, 99%) are operational guidelines (no official basis).

VerdictMeaningNext step
Ready to moveThe pass rate is in the 99% or higher band, there are no authentication failures from your own senders or messages pending review, and the other conditions are metIf the published policy is quarantine, consider changing to reject
Conditional (action needed)The pass rate is 90% or higher, but some points remain to be checkedRun with quarantine while resolving the causes
Not readyThe pass rate is below 90%Resolve the causes of the failures first (below 75%, identify your senders first)
Not enough information to decideToo few report providers, days, or messages, or there are days with no reportCheck the recommended actions for what is missing and how to check it

The screen also shows the breakdown of expected rejections, the basis for the decision (official items are separated from operational guidelines, with sources), and the impact of forwarding (all messages vs. excluding possible forwarding). See Chapter 3 of the manual.

What the dashboard tells you

Status line
One line that says whether emails impersonating your domain were detected, whether your own mail server authentication settings need attention, or whether no issues were detected.
What to do next
For each category that applies, the dashboard lists what to review with its count.
Counts per category
OK / Spoofing suspected / Authentication failures from your own senders / Possible forwarding / Pending review.
Per-domain summary
A table showing email volume, suspected spoofing, and DMARC pass rate for each domain. Select a single domain to narrow the whole dashboard to it.

Classification conditions

OK

DMARC passes. No action needed.

Authentication failures from your own senders

Fails DMARC, and the source IP is within the own mail server IP ranges you registered on the settings screen.

Possible forwarding

Fails DMARC, and the source IP is within a registered forwarding server range, or the receiver reported trusted_forwarder or mailing_list.

Spoofing suspected

Fails DMARC and matches none of the above.

Pending review

Fails DMARC, matches none of the above, and was matched as a known sending service. The current settings screen has no field to register these, so this is normally not assigned.

Classification is done by a rule-based engine. No AI inference or cloud analysis is used. See Chapter 4 of the manual for the detailed conditions.

Key features

Readiness for reject

Verdict, pass-rate gauge, recommended actions, expected rejections, basis for the decision, impact of forwarding, and forwarding server registration.

DMARC aggregate report analysis

Supports ZIP / GZ / XML formats. Extracts source IP, authentication results, and counts, then classifies each entry.

Bounce message analysis

Import bounce messages from Microsoft 365 or a local EML folder and see the recommended next step per category, with the evidence for detection and classification. This is separate from DMARC classification.

Sending server summary and export

Group results by source IP with mail volume, DMARC pass rate, and whether each IP matches what you registered. Export PDF (technical and executive), Excel, and CSV.

Privacy: Analysis results are stored on your PC and are not sent to external AI or cloud analysis services. Microsoft 365 connections are made only when you configure them.

Microsoft 365 permissions: Fetching from the app screen uses only the read permission for shared mailboxes (Mail.Read.Shared) and never deletes, moves, marks as read, or sends mail. The command-line interface (CLI) has a mode that deletes mail after fetching it.
